## 🐛 遇到问题时的排查步骤

### 问题 1：浏览器启动失败

**错误信息示例**：
```
[⚠️ ] MITM 代理未响应
请先在另一个终端运行：python start_mitm_proxy.py
```

**排查步骤**：
1. [ ] 检查终端 1：MITM 是否真的在运行？
   ```bash
   # 在另一个终端运行
   netstat -tlnp | grep 8080
   # 或者
   ps aux | grep start_mitm_proxy
   ```
2. [ ] 等待 2-3 秒后重试
3. [ ] 如果 MITM 没运行，在终端 1 启动它

---

### 问题 2：MITM 未拦截到数据

**症状**：
- 终端 1 没有任何"已缓存"的输出
- `patent_cache.json` 文件不存在或为空

**排查步骤**：
1. [ ] 在浏览器中手动刷新（Ctrl+R）
2. [ ] 确保在搜索框输入了申请人名称
3. [ ] 确保点击了"查询"或"搜索"按钮
4. [ ] 等待搜索结果加载（通常需要 2-3 秒）
5. [ ] 尝试多搜索几个不同的申请人
6. [ ] 在浏览器开发者工具（F12）的"网络"选项卡中，查看是否发送了 HTTP 请求

---

### 问题 3：导入时缓存为空

**错误信息**：
```
[!] 缓存为空，无数据可导入
```

**原因**：MITM 没有拦截到任何数据

**排查步骤**：
1. [ ] 重复问题 2 的排查步骤
2. [ ] 检查浏览器是否真的使用了代理：
   ```bash
   # 在浏览器的地址栏输入：
   # data:text/html,<script>console.log(navigator.userAgent)</script>
   # 或者打开 chrome://settings 查看代理设置
   ```
3. [ ] 尝试访问不同的 CNIPA 页面，看是否能被 MITM 拦截

---

### 问题 4：导入时显示失败记录

**错误信息示例**：
```
[!] 导入失败: 2025110000001 - KeyError: 'zhuanlimc'
```

**原因**：缓存中的数据不完整

**解决步骤**：
1. [ ] 这通常是 MITM 拦截不完整导致的
2. [ ] 重新浏览 CNIPA，让 MITM 重新拦截完整数据
3. [ ] 重新运行 `import_from_cache.py`

## 🎓 技术细节（仅供参考）

### 数据流程

```
浏览器 (配置代理)
  ↓
MITM 代理 (127.0.0.1:8080)
  ↓ 拦截 API: /api/view/gn/patents
  ↓
patent_mitm_scraper.py (_process_record 方法)
  ↓ 提取专利字段
  ↓
patent_cache.json (临时缓存)
  ↓
import_from_cache.py (手动导入)
  ↓ 读取缓存，检查去重
  ↓
detection_log.json (最终日志)
  ↓
export_to_excel() (导出 Excel)
```

### 关键参数

| 参数 | 值 | 说明 |
|------|------|------|
| MITM 监听地址 | `127.0.0.1:8080` | 浏览器代理地址 |
| CNIPA 网址 | `https://cpquery.cponline.cnipa.gov.cn` | 搜索页面 |
| 缓存文件 | `data/patent_cache.json` | 临时缓存位置 |
| 日志文件 | `data/results/detection_log.json` | 最终日志位置 |
| API 端点 | `/api/view/gn/patents` | MITM 拦截的 API |
