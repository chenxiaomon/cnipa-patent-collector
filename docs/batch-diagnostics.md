# 批次记录与环境诊断

用户授权继续实现上一轮第 4、5 项优化。开发和验证均在 Mac 的隔离副本中进行，公司 Windows 实机不在本地。

## 任务范围

- 保存主采集、发文和费用每批的目标、成功、失败、剩余申请号、失败原因及每轮执行记录。
- Dashboard 重启后可读取历史批次，继续同一批次的未完成项。
- 一键诊断实际采集 Python 环境、Chrome/驱动、代理连接、坐标配置及数据目录写入权限，提供 JSON 报告下载。

## 实现约束

- 批次记录归采集器 owner 管理，保存在本机 `data/collection_batches/`，不随 Git 同步；专利业务数据仍只通过 `PatentsDB` 读写。
- 每项只有在专利成功落库后才能记为成功；失败和未尝试必须区分。小批量测试保留未选中的目标，正常结束时视为暂停。
- 续跑沿用原批次并增加执行轮次。采集进程持有批次文件锁，Dashboard 不凭内存任务消失或 PID 猜测采集已经停止。
- 主采集使用与详情采集相同的桌面锁，防止 Dashboard 重启后同时操纵浏览器。
- 诊断不启动采集或浏览器、不访问国知局、不打开专利数据库；权限探测只使用独立临时文件。报告不包含密码、Token 或专利记录。
- Dashboard 保持标准库，不增加前端依赖，沿用任务日志和系统配置页面。

## 验证记录

- Mac 隔离副本完整回归：517 项测试、99 个子测试通过，7 项跳过；按现有 CI 规则排除依赖真实数据库的数据质量测试。
- 最后精简报告详情后，诊断与 Dashboard 接口回归：27 项测试、10 个子测试通过。
- Playwright 检查 1440×1000 与 390×844 视口：批次筛选、分页、失败文本转义、记录下载、同批续跑、刷新后读取、诊断下载与失败重试均通过，无页面异常或横向溢出。使用合成数据，不启动真实采集。
- 新增双进程测试，确认快照读句柄释放后才原子替换文件；Windows 实际系统分支仍需 GitHub Windows CI 验证。
- 批次 JSON 每次状态变化会整体重写；当前适合常规采集批次，频繁万条以上单批需另行评估增量存储。
